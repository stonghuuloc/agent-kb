**What agent-kb reads:** the transcripts of your coding-agent sessions on this machine (Claude Code, and the Claude Desktop Code tab and Cowork), plus chats you save or import yourself, plus the Markdown notes in your vault directory if you set one (indexed locally).

**What leaves this machine:** only what a model sees. When an agent calls `kb_query`, `kb_get`, `kb_resume` or `kb_fork`, the redacted notes it gets back (sessions and vault notes) go to that agent's model provider. The Claude Code plugin's SessionStart hook also adds a short list of recent sessions for the current folder to each new session, so that list goes to the model provider too (off with `AGENT_KB_CONTEXT=off`). The plugin's `UserPromptSubmit` hook also searches the kb with the user's own prompt and adds up to 2 matching notes that way, so those notes go to the model provider too (off with `AGENT_KB_PROMPT=off`). With summaries on, redacted transcript text also goes to the provider you chose: your own `claude` CLI account, or the Anthropic API with your key. Secrets are removed by fixed rules before any write and before any model call. With summaries on, new sessions are summarized automatically (idle sweeps and the session-end hook); a bulk run over past sessions asks first and shows its estimate.

**Where files are written:** one SQLite database in the agent-kb data directory (macOS `~/Library/Application Support/agent-kb`, Linux `~/.local/share/agent-kb`, Windows `%LOCALAPPDATA%\agent-kb`). With a vault directory set, Markdown notes go to `<vault>/<folder>/`. A small marker file `setup-hint-shown` in the same directory records that the setup reminder was shown. With a vault directory set, each summary's journal lines are appended to `<vault>/daily/<date>.md` (folder moved with `AGENT_KB_DAILY_DIR`, switched off with `AGENT_KB_DAILY=off`), created from a template when absent; the rest of that note is never rewritten. `agent-kb backfill-remote` reads your Jira tickets, GitHub PRs and Confluence pages with the tokens in your environment and stores them locally; the fetch itself calls no model, but a stored ticket, PR or page can later reach your model provider when `kb_query` or the prompt hook returns it. Concept notes in `<vault>/concepts/` are written with a generated region that is rebuilt from the local graph. `agent-kb distill` writes proposed rules to `~/.claude/learned-proposals.md`. `fork --to claude` (CLI or `kb_fork`) writes its handoff prompt to a private file in the system temp folder (`agent-kb-fork-*/handoff.md`), which the new session reads; it stays until the OS clears that folder. Nothing else is written.
